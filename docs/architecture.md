# Superfile 架构

`superfile` 可执行文件位于 `crates/superfile-app`，依赖 `superfile-services` 与 `superfile-core`。服务层只依赖核心数据，核心层不执行 I/O。界面使用官方 gpui-kit；工作区没有 `vendor` 或本地框架补丁。

应用层保留编辑器、TextView、表格、文件树和各阅读器实体，统一处理标签、窗口、查找、动作与会话。HTML 直接使用 TextView，不执行脚本。Markdown 通过公开 `MarkdownPlugin` 接口组合图表、任务复选框和图片详情；查找选项及正则替换在核心层实现，不依赖编辑器私有字段。

文件扫描、格式解析、分页、保存、数据库快照和文档渲染在后台执行。任务保留取消句柄，关闭或切换阅读器后停止发布旧结果。文件保存通过原内容检查和临时文件替换避免覆盖外部修改；Windows 文件身份使用卷标识和文件索引。

PDF 使用 Hayro 在后台按需渲染一页，输出 PNG，由 GPUI 显示。源文件先流式复制到私有、无公开路径的快照，再映射以支持随机读取。仅 `snapshot.rs` 中的不可变文件映射边界允许少量 `unsafe`；映射与私有文件共同持有，原文件变更不会破坏已打开的映射。渲染前后检查取消；底层单页渲染期间尚不能立即中止，复杂页面的 CPU/内存行为仍需进一步验证。

Mermaid 使用 Rust 渲染器，保留可终止的子进程边界和文件输出协议，不创建浏览器或原生预览窗口。其他图表引擎尚未完成的类型返回明确错误并保留源码。

Superfile 使用平台应用数据/缓存目录中的独立子目录。诊断日志保存在本地；没有远程配置、安装标识、遥测后台线程或上传通道。没有自动更新器；系统文件关联与正式安装产物仍处于发布阶段的待办范围。
